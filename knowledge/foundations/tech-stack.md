# エンタメで使うAI技術の地図

## 一言で言うと
エンタメに効くAI技術は **「生成（作る）」「理解（読む）」「判断（決める）」「制御（動かす）」** の4系統。
単体の性能より、**レイテンシ・コスト・一貫性・制御性** の4条件を満たせるかで実用性が決まる。

## 4系統

### 1. 生成
| モダリティ | 主な技術 | エンタメ用途 | 実用上の壁 |
|---|---|---|---|
| テキスト | 大規模言語モデル（LLM） | 会話NPC、シナリオ、クエスト、ローカライズ | 設定の一貫性、長期記憶、口調維持 |
| 画像 | 拡散モデル、フローマッチング | コンセプトアート、テクスチャ、背景 | キャラの同一性維持、権利 |
| 動画 | 動画拡散モデル、ワールドモデル | プリビズ、短尺映像、カットシーン | 長尺の一貫性、演出の細かい制御 |
| 3D | NeRF / 3D Gaussian Splatting / 画像→3D生成 | 背景アセット、プロップ、スキャン | トポロジー、ゲームエンジンへの組み込み |
| 音声 | TTS、声質変換 | NPCボイス、吹替、配信 | 感情表現、声の権利 |
| 音楽 | 音楽生成モデル、シンボリック生成（MIDI） | BGM、適応型音楽 | 構成の長期一貫性、権利 |
| モーション | モーション生成、モーションマッチング | アニメーション、ダンス | 物理的妥当性 |
| インタラクティブ世界 | ワールドモデル（行動に応じて次フレームを生成） | 「遊べる動画」、試作 | 状態の永続性、ゲームルールの厳密さ |

### 2. 理解
- **マルチモーダル理解**: 画面・音声・テキストを読み、状況を把握（プレイ実況AI、QA自動化）
- **感情・行動分析**: プレイログ、視聴データ、コメントからの離脱予測・満足度推定
- **コンテンツモデレーション**: UGC・チャットの有害表現検出

### 3. 判断
- **レコメンド**: 次に見る・遊ぶ・買うもの
- **強化学習（RL）**: ゲームAI、バランス調整、自動プレイテスト
- **プランニング/エージェント**: ゲームマスター、ドラマ・マネージャー（物語の進行管理）

### 4. 制御（生成を「作品」にするための技術）
- **条件付け**: 参照画像、ポーズ、深度、スケッチ、スタイル参照
- **ファインチューニング / LoRA**: 自社IPの画風・キャラの学習（権利処理が前提）
- **構造化出力**: LLMの出力をJSONなどに縛り、ゲームロジックと接続
- **RAG（検索拡張生成）**: 設定資料集・世界観Wikiを参照させて一貫性を保つ
- **ガードレール**: キャラ崩壊・不適切発言・ネタバレの防止

## 実用化の4条件

| 条件 | ゲーム内リアルタイム | 制作ツール | 備考 |
|---|---|---|---|
| レイテンシ | 会話なら体感1秒前後が目安、アクションは数十ms | 数秒〜数分でも可 | 体験に乗せるならストリーミング・先読みが必須 |
| コスト | ユーザー1人あたり推論コストが収益を超えないこと | 人件費との比較 | 小型モデル・キャッシュ・オンデバイスで下げる |
| 一貫性 | キャラ・世界観・ルールが崩れない | 同一キャラ・同一画風 | RAG・状態管理・評価が要 |
| 制御性 | ゲームデザイナーが意図を反映できる | ディレクターが修正指示できる | 「全部お任せ」は作品にならない |

## アーキテクチャの定石：LLMをゲームに入れるとき

```
[プレイヤー入力]
      ↓
[ゲーム状態（真実の源泉）] ← ルールはコードが持つ。LLMに持たせない
      ↓ 必要な情報だけ抽出
[プロンプト組立: キャラ設定 + 世界観RAG + 記憶要約 + 現在状況]
      ↓
[LLM] → 構造化出力（セリフ / 感情 / 実行したい行動）
      ↓
[検証層: 行動はゲームルールで許可されたものだけ実行、ガードレール]
      ↓
[演出: TTS・表情・モーション]
```

原則: **LLMは「意図と言葉」を担当し、「事実とルール」はゲームエンジンが担当する。**
これを守らないと、アイテム増殖やルール崩壊などのエクスプロイトの温床になる。
