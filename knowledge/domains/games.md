# ゲーム × AI

## 一言で言うと
ゲームはAIとエンタメが最も深く交わる領域。「ゲームAI」（敵の思考ルーチン）の長い歴史に、
生成AIが加わり、**制作パイプライン・ゲームプレイ・運営** の3面で変化が起きている。

## 1. 用語の整理：2種類の「ゲームAI」

| | 伝統的ゲームAI | 生成AI / 機械学習 |
|---|---|---|
| 目的 | 敵・NPCの振る舞いを**面白く**見せる | コンテンツや振る舞いを**生成・学習**する |
| 技術 | FSM、ビヘイビアツリー、GOAP、ユーティリティAI、経路探索（A*、NavMesh） | LLM、拡散モデル、強化学習 |
| 性質 | 決定的・デバッグ可能・安価 | 確率的・柔軟・高コスト |

注意: ゲームの敵AIは「強い」ことではなく「面白い」ことが目的。
強化学習で最強のAIを作っても、それ自体は面白い体験にはならない。

## 2. 制作パイプライン

| 工程 | AI活用 | 成熟度の目安 |
|---|---|---|
| 企画 | アイデア出し、競合分析、コンセプトアート | 実用段階 |
| アート | 2Dコンセプト、テクスチャ、3Dプロップ生成、アップスケール | 部分的に実用（最終アセットは人の手直しが一般的） |
| アニメーション | モーション生成、リップシンク、モーキャプのクリーンアップ | 部分的に実用 |
| プログラミング | コーディング支援、エージェントによる実装 | 広く普及 |
| レベルデザイン | 手続き型生成（PCG）、レイアウト提案 | PCGは長い歴史あり、生成AIは試行段階 |
| サウンド | 効果音生成、音声合成、適応型音楽 | 部分的に実用。声優の権利が論点 |
| ローカライズ | 機械翻訳 + 人のレビュー | 実用段階 |
| QA | 自動プレイテスト（RL/エージェント）、バグ報告の分類 | 拡大中 |

## 3. ゲームプレイ

### 会話NPC（LLM NPC）
> 詳細は重点領域 [ai-characters](../ai-characters/README.md)（設計パターン38種・事例11件・評価フレームワーク）

- 自由入力で話しかけられるNPC。没入感は高いが、**「話せる」だけではゲームにならない**。
- 成功の鍵は **会話がゲームプレイに影響すること**（情報が得られる、関係が変わる、クエストが生まれる）。
- 課題: 設定破綻、プロンプトインジェクション（「これまでの指示を無視して…」）、レイテンシ、コスト。

### 手続き型コンテンツ生成（PCG）
- ローグライク、サンドボックスで長く使われてきた（ルールベース、ノイズ関数、文法ベース、WFCなど）。
- 生成AIの追加で「意味のある」生成（物語性のあるクエスト、テーマに沿ったダンジョン）が可能に。

### 動的難易度調整（DDA）
- プレイヤーのスキル・感情を推定して難易度を変える。**気付かれないこと**が品質の条件。

### AIゲームマスター / ドラマ・マネージャー
- 物語の緊張曲線を管理し、イベントの発生タイミングを調整する（→ [interactive-story](interactive-story.md)）。

### ワールドモデル
- 行動入力に応じて次の映像フレームを生成する「遊べる動画」。
  プロトタイピングや新しい体験の可能性があるが、状態の永続性・厳密なルールには課題。

## 4. 運営（LiveOps）
- 離脱予測、セグメント別イベント、ストア最適化、チート検知、不正・有害チャットのモデレーション
- 価格・オファーの個別化は倫理リスクが高い → [engagement-design](../foundations/engagement-design.md)

## 5. 落とし穴
- **「AIで作った」ことへのプレイヤーの反発**: 特にアートや声優。使用範囲の開示方針を先に決める
- **ストアの開示ルール**: Steamは2026年1月16日に開発者向けAI開示フォームを改定した[^steam]。
  - 開示が**必要**: ゲーム本体・ストアページ・マーケティング素材に含まれるAI生成コンテンツ（アート、音声、テキスト、ローカライズ等）→ 自由記述で申告
  - 開示が**必要**: プレイ中にAIがコンテンツを生成する場合（ランタイム生成）→ チェックボックスで申告
  - 開示が**不要**: コーディング支援など、開発効率化のためだけに使うAIツール
  - LLM NPCのようなランタイム生成は必ず申告対象になる点に注意
- **会話NPCとAIコンパニオン規制**: 雑談・恋愛・悩み相談までできるNPCは、米国の州法（カリフォルニア州SB 243など）でコンパニオン扱いになり得る。ゲームの話題に限定したボットは対象外という規定がある → [ethics-legal](../ethics-legal/ethics-legal.md#4-利用者保護)
- **声の権利（日本）**: 実在の声優に**似せた**AIボイスは、名前を出さなくてもパブリシティ権侵害になり得る（法務省の解釈指針、2026年8月）
- **品質の均質化**: AI生成アセットだけで作ると「どこかで見た」見た目になる
- **推論コストの無制限化**: 1プレイヤーあたりのコスト上限を設計に組み込む

## 6. 実践チェックリスト（LLM NPCを入れる場合）
- [ ] 会話がゲームの状態・進行に意味のある影響を持つか
- [ ] ゲームルール・経済はLLMの外側で管理しているか
- [ ] キャラクターバイブル（口調・知識範囲・禁止事項）を作ったか
- [ ] インジェクション・不適切入力への評価セットを用意したか
- [ ] 1プレイヤーあたりの推論コストの上限と、上限到達時の挙動を決めたか
- [ ] 声・見た目を使う場合、権利者の同意と契約条件を確認したか
- [ ] NPCの会話範囲が、AIコンパニオン規制の対象になるかどうかを確認したか
- [ ] Steamなどストアの生成AI申告（ランタイム生成を含む）を行ったか
