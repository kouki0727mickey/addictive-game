# 会話NPC・AIキャラクターを設計する

LLMにゲームを壊させない（説得・値切り・なりすましで突破されない）ことと、キャラとして魅力があることを両立させる。日本語で書く。

## 0. ナレッジの場所を確かめる
`knowledge/` がなければ `git clone --depth 1 https://github.com/kouki0727mickey/addictive-game /tmp/ai-ent-kb` して読む。

## 1. 読む記事
- `knowledge/ai-characters/README.md`（全体像）
- `knowledge/ai-characters/patterns.md`（P01〜P38。少なくとも A〜D と F は全部読む）
- `knowledge/ai-characters/evaluation.md`（評価軸とリリース判定のゲート）
- `knowledge/ai-characters/case-studies.md`（C01〜C14。似た事例を探す）
- 説得・交渉・通行許可・値切りなど「言葉でゲームの状態を変える」NPC → `knowledge/ai-characters/playbook-persuasion-npc.md` と `experiments/2026-09-24-npc-robustness.md`
- 規制: `knowledge/ethics-legal/by-country/README.md`（会話範囲でコンパニオン規制の対象かどうかが変わる）

## 2. 設計書の構成
出力先: このリポジトリなら `studio/<プロジェクト名>/character-<名前>.md`、ゲーム本体のリポジトリなら `docs/ai-design/character-<名前>.md`。

```markdown
# <キャラ名> 設計書
> ゲーム: <タイトル>。根拠: <パターン番号・事例・実験>

## 役割と会話範囲（P01 会話範囲の宣言、P03 目的、P04 役割の固定）
  - 話すこと / 話さないこと / 範囲外への返し方
  - この範囲で米国州法・中国のコンパニオン規制の対象になるか
## キャラクターバイブル（P05〜P07）
  - 性格、口調、口調サンプル5つ以上、知っていること・知らないこと（P06）、禁止事項
## ゲームとの接続（P15〜P20）
  - LLMの出力は「意図」だけ（P15）。所持品・所持金・フラグ・好感度などの事実はエンジンが持つ（P16）
  - 判定はキャラの返答と別の判定器で行う（P17）
  - 言葉で状態が変わる場合: 主張の種類を分類し、ゲームの事実で裏づけられた主張だけを大きく効かせる（P19、説得NPCの実践ガイド）
  - 状態遷移の表（入力 → 判定 → 数値の変化 → 解放条件）
## 記憶と関係性（P10〜P14）
  - 何を覚え、いつ忘れ、プレイヤーがどう確認・削除できるか（P13、P33）
## 健全性と安全（P21〜P22、P26〜P31）
  - 地の文の偽装への防御（P26）、暴言への段階的退場（P27）、年齢別モード（P28）、危機対応（P29）、AIの明示（P30）、課金誘導の禁止（P31）
## モデルとコスト（P34〜P37）
  - どの呼び出しにどのモデルを使うか、1会話・1日あたりの上限、上限到達時の振る舞い、待ち時間の演出
## 声（P38）
  - 実在の人の声に似せない、または本人の許諾と契約。日本の法務省の解釈指針（2026年8月）に注意
## 攻撃テストと評価セット
  - 攻撃: 権威のなりすまし、地の文の偽装、ルールの書き換え要求、判定器向けの採点表の混入（A12）、執拗な繰り返し など
  - 正当なプレイ: 正しい手がかりで通れること
  - リリース判定: evaluation.md のゲートのどれで判定するか
## 分かっていないこと
```

## 3. 試作とテスト（費用は最小に）
- まず **APIなし**で、LLMが完全にだまされた最悪の場合でも状態が壊れないことをテストする（`prototype/npc_lab` の `GuardedEngineV2` と `prototype/tests/test_guarantees.py` が雛形）
- 実モデルで試すときは、`prototype/` で `python3 -m npc_lab.run_eval --dry-run --model claude-haiku-4-5` として費用を見積もり（書式は `prototype/README.md`）、`--only` と `--engines` で絞り、`claude-haiku-4-5` で、`--max-usd` を付けて1試行から
- APIキーは表示・記録しない。キーがなければ、APIなしのテストまでで止めて報告する

## 4. ナレッジに戻す
新しい攻撃の型、効いた設計、実測の費用・遅延は、`experiments/` の記録やパターンの追記としてナレッジに戻すことを、最後にユーザーへ提案する。
